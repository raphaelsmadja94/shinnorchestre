# Skill : Clean Code

## Objectif
Améliorer la lisibilité, la maintenabilité et réduire la dette technique.

## Quand le charger
- Revue de code.
- Refactorisation.
- Audit de qualité.

## Quand ne pas le charger
- Tâche sans modification de code.
- Prototype jeté sans intention de maintenir.

## Checklist
- Lisibilité immédiate.
- Responsabilités cohérentes.
- Complexité maîtrisée.
- Conventions respectées.

## Bonnes pratiques
- Noms explicites.
- Fonctions courtes et focales.
- Suppression du code mort.
- Commentaires utiles uniquement.

## Erreurs fréquentes
- Code dupliqué.
- Fonctions trop longues.
- Couplage fort sans abstraction.
- Comments inutiles ou obsolètes.

## Critères de validation
- Revue par un pair.
- Temps de compréhension réduit.
- Impact limité d’un changement.

## Règles opérationnelles

### Lisibilité
- Privilégier la clarté à la concision excessive.
- Éviter les abréviations obscures.

### Structure
- Encapsuler les comportements métier.
- Limiter la profondeur d’imbrication.

### Maintenance
- Supprimer le code mort rapidement.
- Préférer l’ajout de tests à la documentation redondante.

## Processus d’intervention
1. Repérer les zones à risque.
2. Proposer des améliorations par périmètre.
3. Valider sans casser l’existant.
4. Produire un rapport court.
